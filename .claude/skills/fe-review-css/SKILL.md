# CSS and layout pass (CSS)

| ID | Check | How to verify | Default sev |
|---|---|---|---|
| CSS-01 | Layout survives 320px | Trace the top-level grid/flex: fixed px columns, `min-width`, or fixed panels that exceed 320px total with no breakpoint | major |
| CSS-02 | Nothing scrolls sideways | No element wider than its container: fixed widths inside padded parents, `100vw` next to padding, unwrapped long strings/URLs (`overflow-wrap`/`min-width: 0` on flex children). **Ownership:** CSS-02 owns content that pushes the *layout* wider than the viewport; CSS-04 owns text that clips or overlaps *within* a box that holds its size. Same element can only be reported once | major |
| CSS-03 | Text reflows at 200% zoom / 400% (1.4.10) | Layout uses relative units and wrapping rather than absolute positioning locked to viewport pixels; no `overflow: hidden` clipping text | major |
| CSS-04 | Text growth is handled | Enumerate every element that renders user-supplied or imported text, then verdict the full list — partial coverage is what makes two runs disagree. Each must tolerate +30–50% length (translation, long names) without clipping or overlap, and any truncation (`nowrap`, `ellipsis`, `line-clamp`) carries a `title`/tooltip with the full value | minor |
| CSS-05 | Colour scheme is complete | If a scheme is declared (`color-scheme`, `prefers-color-scheme`, a dark theme), every surface, border, form control and third-party widget is covered — no inherited default-light control on a dark panel | major |
| CSS-06 | Motion respects the user | List every `transition`, `animation` and scroll-behaviour in scope. If none exceeds ~200ms and none loops, that is a `PASS` (motion exists and is already safe), not `N/A`. Otherwise each qualifying one must be disabled under `prefers-reduced-motion: reduce` | major |
| CSS-07 | Stacking is deliberate | z-index values come from a small named scale; no ad-hoc `9999`; overlays/menus/tooltips cannot be covered by a sibling | minor |
| CSS-08 | No `!important` escalation | Each `!important` is justified (third-party override) or removed | minor |
| CSS-09 | Values come from tokens | **Colours and radii only** — spacing literals are a style preference, do not report them here. The bar is mechanical: the same colour literal written three or more times, or one colour defined twice with different hexes, is a `FAIL`; a one-off literal is a `PASS` | minor |
| CSS-10 | Interaction states are styled | `:hover`, `:focus-visible` and `:active` are each defined for interactive elements — a stylesheet with `:hover` but no `:active` anywhere is a `FAIL`. A global `:focus-visible` rule satisfies the focus half. `:disabled` is exempt when no control in scope is ever disabled | major |
| CSS-11 | No hover-only affordance | Anything revealed only on `:hover` has a non-hover route (always visible, focus, or tap) for touch and keyboard | major |
| CSS-12 | Selectors and units are sane | No deep descendant chains that break on markup changes; no positional targeting of controls (`:nth-of-type`/`:nth-child`/`+`-chains used to reach one button among siblings — inserting a button silently restyles the wrong one, so this is a `FAIL`); no `px` for font sizes where `rem` is expected, no fixed `line-height` in `px` | minor |
| CSS-13 | Fixed/sticky elements do not trap content | Sticky headers/footers reserve space or offset scroll; content is not permanently hidden behind them, including at small heights. Also owns **viewport clamping**: a menu, popover or tooltip positioned from pointer or element coordinates must flip or clamp inside the viewport — one opened near the right or bottom edge that renders partly off-screen is a `FAIL` | major |
| CSS-14 | Dead and duplicated CSS | Two directions, both mechanical. (i) A selector matching no element the components in scope render — **skip selectors namespaced to a library** (`.react-flow__*`, `.rc-*`): that markup is out of scope, so it is neither confirmable nor dead. (ii) A `className` on an element in scope that **no rule in scope matches for that element** — the unit is the class *on that element*, not the class name in the abstract, so a class styled only under a different ancestor is inert here and a `FAIL`. Plus duplicated declarations: the **same selector** setting the same property twice. A base rule and a later override — grouped or not, equal specificity or higher — is the cascade working as designed, not a finding | minor |
