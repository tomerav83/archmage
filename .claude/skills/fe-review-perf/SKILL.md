# Performance pass (PERF)

Targets at p75: **LCP < 2.5s, INP < 200ms, CLS < 0.1**. INP is the most
commonly failed of the three — weigh handler work accordingly.

| ID | Check | How to verify | Default sev |
|---|---|---|---|
| PERF-01 | LCP path is short | Entry HTML has no render-blocking sync scripts or external stylesheets in `<head>` beyond the bundle; the largest element is not gated behind a data fetch that could be preloaded or server-rendered | major |
| PERF-02 | Fonts do not block or shift | Web fonts use `font-display: swap`, are preloaded and self-hosted; no runtime font CSS from a third-party origin | major |
| PERF-03 | Images are sized and cheap | Every `img`/`video`/`iframe` has explicit `width`/`height` or a CSS aspect-ratio box; below-fold images use `loading="lazy"`; no full-size asset rendered into a thumbnail. Raster images served at more than one size need `srcset`/`sizes`, and photographic assets should be WebP/AVIF rather than PNG/JPEG | major |
| PERF-04 | Nothing shifts after paint | Late-arriving content (banners, async lists, injected icons/SVG) reserves space; no layout animation of `width`/`height`/`top`/`left` where `transform` works | major |
| PERF-05 | Event handlers stay under the INP budget | Find handlers on `mousemove`/`pointermove`/`scroll`/`resize`/`input`/`drag`: they must not do O(n) work over app state, serialize, write storage, or set state on every event without throttling, rAF batching or a transition. **Partial deferral does not clear this check:** PERF-05 judges the *urgent* path only. If the handler still does O(n) work before yielding, `FAIL` here even when a downstream consumer is wrapped in `useDeferredValue` — that mitigation belongs to PERF-14, and the two are not reported together | blocker |
| PERF-06 | Persistence is not on the render path | Writes to `localStorage`/`IndexedDB`/network triggered by every state change or keystroke must be debounced or moved off the interaction; `JSON.stringify` of the whole document per change is a fail | major |
| PERF-07 | Derived values are computed once | Expensive derivations (sorts, filters, graph walks, `Object.entries` over large maps) run in `useMemo`/selectors, not inline in render or repeatedly in the same render. **Ownership:** PERF-07 owns work that is expensive on *every* render regardless of what changed. If the cost only matters because a cheap frequent change (drag, keystroke, hover) keeps re-triggering it, that is churn — report it under PERF-15 and `PASS` here | major |
| PERF-08 | Context and props keep stable identity | Context `value` is memoized, as are object/array/function props handed to a child wrapped in `React.memo` — a new literal per render defeats the memo. An inline arrow passed to a component that is *not* memoized costs nothing: that is a `PASS`, not a finding | major |
| PERF-09 | State lives at the right level | High-frequency state (pointer position, input text, hover) is not held in a provider or root component that re-renders the whole tree. **Ownership:** `FAIL` only when the state could move down — it is used by one subtree and nothing else needs it. If the value genuinely belongs at that level (document state, the edited entity's own fields), the placement is right and the re-render cost is PERF-15's, not this check's | major |
| PERF-10 | Long lists are bounded | Any list that can exceed ~200 rows is virtualized, paginated, or explicitly capped. **The bar is the reachable input, not the typical one:** if a size limit exists anywhere on the path that produces the list (an import cap, a page size, a fixed catalogue), the list is bounded and this is a `PASS`. If the only limit is a byte cap on an import — which permits thousands of rows — or there is no limit at all, it is a `FAIL`, and a virtualization flag the code leaves at its off-by-default value does not count as bounding | major |
| PERF-11 | Runtime third-party requests | No dependency that fetches assets, icons, or config from a remote API at render time on the critical path — it becomes latency and an availability dependency | major |
| PERF-12 | Bundle weight is justified | Read `package.json`. `FAIL` on a mechanical fact only: a dependency nothing imports, two dependencies doing the same job, a whole-library import where a documented subpath exists, or a large optional view with no route/feature code splitting. **"This could have been hand-written" is not a finding here** — a used, single-purpose dependency is a `PASS` however small the job | minor |
| PERF-13 | Nothing leaks | Every `addEventListener`, `setInterval`/`setTimeout`, `ResizeObserver`/`IntersectionObserver`, subscription, `createObjectURL` and `AbortController` has a matching teardown on the path that created it | major |
| PERF-14 | No accidental work amplification | Trace what each memo/effect actually re-runs on: a cheap or cosmetic change (a drag position, a hover, a keystroke) must not invalidate an expensive derivation over the whole data set. Also flag effects that write state they depend on, render-triggered fetches without a cache, and re-parsing the same JSON per render. **Mitigation counts:** a `useDeferredValue`, a `startTransition` or a debounce that keeps the recomputation off the urgent frame is a `PASS` — the work still happens, but it no longer blocks the interaction, which is what INP measures | major |
| PERF-15 | Static subtrees are isolated from churn | A component holding high-frequency state (drag position, input text, hover, timer) must not re-render an expensive static sibling on every tick. The cheapest fix is composition — take the subtree as `children` so the parent's state cannot invalidate it — before reaching for `memo`. Two conditions, both required for a `FAIL`: the subtree is **costly** (renders ~100+ elements, or mounts a third-party canvas/graph/editor widget) *and* it is **isolatable** — it does not itself read the churning state. A subtree that re-renders because it genuinely consumes that state cannot be lifted into `children`; it is a `PASS` here and its cost, if any, is PERF-07's. Cost that appears only in a reachable configuration (a large board, a selected node) counts as costly. **PERF-15 owns re-render churn.** When this check, PERF-07 and PERF-09 all match one design, report it here once and `PASS` the other two — one defect, one row | major |
